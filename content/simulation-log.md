## 记录问题，而不仅是文件名

首先写明本次运行试图回答什么问题。随后记录几何、材料参数、载荷、边界条件与求解设置。

## 使用固定的记录模板

| 记录项目 | 建议内容 |
| --- | --- |
| 运行标识 | 日期与简短名称 |
| 输入版本 | 数据、几何和脚本版本 |
| 关键参数 | 数值、单位与来源 |
| 检查结果 | 收敛信息与异常 |
| 输出位置 | 数据与图表的保存路径 |

## 将异常也保留下来

失败的运行可能帮助解释下一次修改。记录错误信息、触发条件和已经尝试的处理方式，而不是只保留成功截图。

## 区分观察与解释

先写观察到的数值或现象，再说明你的解释。尚未验证的解释应该明确标注，不要写成已经成立的结论。
